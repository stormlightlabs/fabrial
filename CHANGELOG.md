# Changelog

What each fabrial release changes for a repository that installs it. The
Release workflow writes each release's section from the commit subjects since
the last release, and the owner edits it in the release pull request.
Pull requests do not edit this file. A line the owner writes under Unreleased
stays, and replaces the generated line for the PR it names as `(#N)`.

## Unreleased

- Show pull request and run status in Pi (#47)

- Collect pull request status in the Pi package (#46)

## 0.3.3 - 2026-10-24

- Run CI only when it has work to do (#41)

- Give the controlled dispatch test more time (#40)

## 0.3.2 - 2026-10-24

- An edit that lands while the Review gate posts the squash message no longer
  leaves an older message newest: the gate reads the pull request again after
  it posts (#37).

- The squash body keeps `Session:` lines unless they name a link, and no
  longer tracks code blocks, so a block cannot hide the footer or an
  attribution line (#37).

- Write the changelog in the release pull request (#38)

## 0.3.1 - 2026-10-24

- The squash message the Review gate posts ends its subject with the pull
  request number, such as `Add Pi dispatch (#21)`.

- Release tag finds the release pull request from the merge commit, so a
  release merged with any squash message is tagged. Run it from the Actions
  tab with a commit to tag a release merge it missed.

## 0.3.0 - 2026-10-24

- The Review gate no longer turns on auto-merge. A finished review marks the
  pull request ready, sets `storm/review` and posts the squash message; the
  owner merges it by hand or turns on auto-merge. `/storm:stop` still turns
  auto-merge off (#32).

- Keep completed reviews green for native GitHub stacks. GitHub does not support
  their auto-merge, so the bot posts the squash message for manual stack merging.

- Add an opt-in real-sandbox acceptance run for asynchronous Pi workers,
  including conversation responsiveness, restart, steering, cancellation,
  timeout, pane loss, and cleanup.

- Restore worker subscriptions and replay undelivered notifications after Pi
  reload or resume. Add `/worker-watch`, `fab worker list`, and conservative
  cleanup recovery. Recovery never starts a replacement or signals old PIDs.

- Make the Pi `agent` tool return a worker ID after launch. A session-scoped
  observer delivers completion and blockers without model polling. Add
  `agent_control` and the driver-only `/worker-steer` command.

- Add a pipe-based Pi RPC bridge, replayable `fab worker events`, and explicit
  head-pinned `steer`. Workers can report progress, blockers, and questions;
  blockers and questions stop the worker and return control to the driver.

- Add `fab dispatch --detach` and `fab worker inspect`, `cancel`, and `wait`.
  The recorder cleans up independently of the caller; results and progress
  remain in the private registry.

- Retain private, credential-free worker records and redacted final results
  after dispatch cleanup, with run/worker IDs and resource ownership.

- Fix App JWT authentication in the local issuer. The host now needs curl
  with `--header @-` support.

- Add preview `fab dispatch` for four fresh Pi review roles and a root Pi
  `agent` tool, with host tmux, pinned whole-worker isolation, explicit trusted
  instructions, and a local repository-restricted App issuer. Dispatch runs in
  Rust without a Python runtime. Installs include Pi role models.

- Skills watch checks after review, preserve progress across orchestrator
  sessions, and refresh local `main` and clean up task worktrees after merge.
- Quote optional skill argument hints so Pi can load the review, adversarial
  review and handoff skills.
- `fab init` and `fab update` record the release alone in
  `.github/fabrial.toml`, without the commit, so open pull requests no longer
  conflict on that line. The storm skill checks that a pull request still
  merges before posting `Review finished`.

## 0.2.0 - 2026-10-24

- `fab update` refreshes an install and refuses to downgrade one, and
  `fab check` reports drift. `fab init` is now for the first install only.
- The gate leaves auto-merge off on a pull request GitHub would merge now and
  posts the squash message instead, fails `storm/review` when GitHub refuses
  auto-merge, and keeps auto-merge off after a late `/storm:stop` (#10, #11).
- A pull request's description above its footer line becomes the squash
  commit's body, without attribution lines or session links (#13).
- On pickup, the handoff skill checks `arcl task explain` before unparking, and
  passes `--force` to `arcl task start` only when the operator asks (#12).
- PR bodies leave out attribution lines and session links (#9).
- `fab init` installs the workflows, gate, skills and agents (#8).
